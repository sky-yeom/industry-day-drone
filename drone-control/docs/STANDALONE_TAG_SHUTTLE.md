# AprilTag 카메라·좌우 왕복 단독 시험

Speech, Azure, 웹 대시보드, HTTP 도구 서버를 실행하지 않고 휴대폰 앱과 직접
통신하는 시험입니다. 기존 시험의 영상·태그 인식·하방 높이 상승 방식을 사용하고,
새 `.5` 앱의 통신 오류 처리와 명령 유효시간 검사는 유지합니다.
기존 Speech 실행기와 과거 counted trial은 변경하지 않습니다.

## 배치와 이동

사용자가 확인한 배치(기체가 벽을 보는 방향):

```text
벽:       1       2       3       6
바닥:                            0
                                 ↑ 출발 / 복귀
```

`0`은 바닥의 출발·착륙 기준, `6`은 정면 벽의 출발·복귀 기준입니다.
방문 경로는 **6 → 3 → 2 → 1 → 2 → 3 → 6**입니다.

1. 영상 수신과 지상 상태를 확인하고 이륙합니다. 지상에서 너무 가까운 바닥 태그가
   화면에 잘릴 수 있으므로, 이전 성공 시험처럼 이륙 후 바닥 0을 필수 확인합니다.
2. 바닥 0이 확인되면 하방 센서 표시 1.4m까지 최대 8초 동안 상승합니다.
3. 카메라를 정면으로 돌리고 벽 6을 확인합니다.
4. 왼쪽으로 3, 2, 1을 순서대로 방문하고 오른쪽으로 2, 3, 6에 복귀합니다.
5. 정지 명령과 RC 제어권 반환을 확인합니다. 착륙은 RC로 직접 합니다.

순항 중 전후 이동·기체 회전·태그 높이에 따른 상하 보정 명령은 보내지 않습니다.
태그의 영상 가로 중심을 기준으로 각 방문을 확인합니다. 예상하지 않은 번호가
보여도 경로를 건너뛰지 않습니다. 각 방문에는 3초 정지를 둡니다.
태그를 보고 복귀하는 방식이므로 출발 좌표의 센티미터 단위 재현을 보장하지 않습니다.

## 실행

저장소 루트에서 아래 명령을 실행합니다. Windows 실행기는 저장소 안의
`drone-control/.venv/Scripts/python.exe`를 사용합니다. 다른 환경은 `-PythonPath`로
지정합니다. PC 환경 설치는 [새 PC 준비 안내](NEW_PC_SETUP.md)를 참고하세요.
음성 시험과 달리 이 단독 시험에는 Azure 로그인이 필요하지 않습니다.

```powershell
# 계획 확인: 네트워크 연결 없음
./drone-control/trials/START_TAG_SHUTTLE.ps1

# 카메라 인식만: 이동·이륙·짐벌 조작 없음
./drone-control/trials/START_TAG_SHUTTLE.ps1 -Mode Camera -PhoneIp "휴대폰IP"

# 실제 이륙과 좌우 왕복 시험
./drone-control/trials/START_TAG_SHUTTLE.ps1 -Mode Flight -PhoneIp "휴대폰IP"
```

실제 IP 주소로 바꿔 실행합니다. 카메라 단독 시험에서는 RC로 카메라 방향을
맞춥니다. 카메라 시험을 종료한 뒤 비행 시험을 실행합니다. 다른 PC 비행 실행기가
같은 앱의 제어·영상 연결을 동시에 사용하지 않도록 합니다.

기본 개인 설정 경로는 `drone-control/pc/config.tag-shuttle.local.json`입니다.
새 PC에서는 기존 개인 설정을 비공개로 옮기거나 `-ConfigPath`로 지정합니다.
키·arm token은 출력하거나 Git에 올리지 않습니다. 실행 때 현재 휴대폰 IP를
명시하므로 과거 PC의 주소를 자동으로 재사용하지 않습니다.

시험 프로필은 `trials/profiles/standalone_tag_6321236.json`입니다.
벽 배치·경로는 확인됐으며 태그 크기는 별도 확인 항목입니다. `tag_size_m`는
태그 검은 정사각형 한 변의 실제 길이입니다. 확인 전에는 `tag_size_confirmed=false`로
두어 비행 실행을 막습니다. 바닥 0을 포함해 태그 크기가 다르면 이 공통 크기
프로필을 그대로 사용하지 않습니다.

## 기록과 중단

- 카메라 단독: `pc/logs/tag-camera/<실행ID>/observations.jsonl`, `summary.json`.
  번호, 역할, 영상 중심·모서리, 인식 품질, 프레임 나이와 연결 상태를 기록합니다.
  설정에 크기가 없는 새 태그 6도 번호는 인식하며 미확인 거리값을 만들지 않습니다.
- 비행: 기존 PC JSONL 원시 요청·ACK·센서값과 태그 관측·확인 사진을 기록합니다.
- PC 장애물 거리 임계치에 따른 정지는 추가하지 않습니다. 기체 펌웨어의 회피
  설정을 변경하지 않으며 센서의 범위 밖 값·오래된 값도 기록에 보존합니다.
- 실제 `.5` 앱, 최신 지상·모터·RC 상태, 영상과 높이 데이터가 필요합니다.
  배터리 최소 30%, 최대 기울기 1.5도, 구간 45초·전체 240초 범위입니다.
  명령 응답 불명, 연결·제어권 상실, 오래된 영상에서는 자동 재실행하지 않습니다.
- Ctrl+C 또는 오류 시 정지·제어 해제를 시도하고 확인 결과를 출력합니다.
  RC 반환 확인과 실제 착륙 완료는 구분합니다.

## 검증 상태 (2026-09-10)

- 전체 PC 단위 테스트 182개 통과: 기존 141개 + 카메라 단독 15개 + 새 왕복 26개.
- 실제 설치된 PyAV/OpenCV/pupil로 로컬 시험 영상의 ID 0·6을 3프레임 모두 인식.
- PowerShell 계획 실행, 문법, 잘못된 IP의 연결 전 거절 확인.
- 새 태그 6 경로의 기체 연결·실제 비행은 아직 수행하지 않았습니다.
- 벽 배치·방문 순서는 사용자 확인 완료. 15cm 공통 태그 크기는 응답 대기이며
  프로필의 `tag_size_confirmed`는 아직 `false`입니다.
