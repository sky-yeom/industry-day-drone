## 2. 오늘 저녁에 바뀐 제어 로직 (Codex 오후 작업 이후)

### 2.1 지나침 보정을 펄스에서 **연속 비례 기울기**로
`trials/id1_pair_framing.py`

- 14:51 비행 분석: 좌측 0.28 m/s로 접근하던 태그가 도착 구간(85~95 %)을 1.2 초 만에
  통과해 화면 밖으로 사라졌고, 그 뒤 0.25도×0.25초 펄스(가속 약 0.04 m/s²)로는 기체가
  몇 mm도 못 돌아와 33 초 정지 후 45 초 시간 초과.
- 변경: 정지·안정(0.6 초, 수평속도 ≤ 0.08 m/s) 후 태그가 구간에 들어오거나 반대편으로
  넘어갈 때까지 **0.25~0.6도 연속 기울기** 유지. 태그가 사라지면 사라진 방향으로
  **0.6도 연속 재탐색**(마지막 관측 후 6 초 이내), 다시 보이면 정지·안정 후 비례 보정.
- 우측 보정 한계 +0.25도 → **+0.6도** (`ShuttleClient.lateral_bounds`).
- 15:23·15:26 비행에서 실제 확인: 88.5 % → 소실 → 우측 재탐색 → 88.9 % 재포착 →
  85 % → 좌측 보정 → 88.3 % 촬영.

### 2.2 `is_flying` 신선도 오탐 제거
`trials/standalone_tag_shuttle.py` — `FLIGHT_STATE_FRESH_S = 1.5`

- 폰이 `IsFlying`을 약 0.54 초 주기로 읽는데 PC 검사 한계가 0.5 초라 무작위로 중단됨
  (15:23 비행, 촬영 직전 age 517 ms; armed·MSDK·고도 전부 정상이었음).
- 비행 플래그만 1.5 초(폴링 3회 누락)까지 허용. 영상·속도·고도 신선도는 0.5 초 유지.

### 2.3 첫 방문 태그 전부에 모크 구도 적용
`trials/standalone_tag_shuttle.py` `run()` / `capture_id1_pair(..., departure, expected)`,
`PairFramingGate(tag_id=...)`

- 이전에는 ID1만 구도 촬영, ID2·ID3은 통과 기준으로 찍혔음.
- 지금은 outbound 구간(6→1, 1→2, 2→3) 모두 같은 게이트로 촬영. 결과의

## 4. 현장 운용 메모

- **폰 IP는 핫스팟마다 바뀝니다.** 오늘 172.16.251.9 → **10.244.155.20**. 실행 시
  `-PhoneIp`로 현재 값을 넘기고, PC는 폰 핫스팟(SSID "김하종")에 붙어 있어야 합니다.
  확인: PC 기본 게이트웨이가 폰이고 9997/9998/9999 포트가 열려 있으면 됩니다.
- **비행제어기 조회 오류** `REQUEST_HANDLER_NOT_FOUND`(카메라·짐벌·RC는 정상인데
  FlightController 키만 실패): USB 재연결로 안 풀리면 **앱 강제종료 후 재실행**으로
  복구됐습니다. PC에서 보낼 수 있는 복구 명령은 없습니다(앱의 자동 복구는 DISABLED).
- 이륙 전 스크립트가 요구하는 것: 지상·모터 정지·RC 권한 최신값, 브리지 `.6`,
  배터리 ≥ 30 %, 최신 영상. 아니면 이륙하지 않고 종료합니다.
- 착륙은 항상 RC로 직접. 스크립트는 착륙 명령을 보내지 않습니다.
