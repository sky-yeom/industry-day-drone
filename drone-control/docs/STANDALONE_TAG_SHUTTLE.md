# AprilTag 카메라·좌우 왕복 단독 시험

Speech, Azure, 웹 대시보드, HTTP 도구 서버를 실행하지 않고 휴대폰 앱과 직접
통신하는 시험입니다. 기존 시험의 영상·태그 인식·하방 높이 상승 방식을 사용하고,
새 `.6` 앱의 통신 오류 처리와 명령 유효시간 검사는 유지합니다.
기존 Speech 실행기와 과거 counted trial은 변경하지 않습니다.

## 배치와 이동

사용자가 확인한 배치(기체가 벽을 보는 방향):

```text
벽:       3       2       1       6
바닥:                            0
                                 ↑ 출발 / 복귀
```

`0`은 바닥의 출발·착륙 기준, `6`은 정면 벽의 출발·복귀 기준입니다.
방문 경로는 **6 → 1 → 2 → 3 → 2 → 1 → 6**입니다.

1. 영상 수신과 지상 상태를 확인하고 한 번 이륙합니다. 자동 이륙이 끝나고 정상 모드에서
   수직 속도가 안정된 것을 2초간 확인한 후 제어권을 요청합니다. 지상에서 너무 가까운 바닥 태그가
   화면에 잘릴 수 있으므로, 이전 성공 시험처럼 이륙 후 바닥 0을 필수 확인합니다.
2. 바닥 0이 확인되면 하방 센서 표시 1.5m까지 최대 8초 동안 상승합니다.
3. 카메라를 정면으로 돌리고 벽 6 전체가 영상 안에 보이는지 확인합니다. 중앙 ±80px 정렬은 요구하지 않습니다.
4. 왼쪽으로 1, 2, 3을 순서대로 방문하고 오른쪽으로 2, 1, 6에 복귀합니다.
5. 정지 명령과 RC 제어권 반환을 확인합니다. 착륙은 RC로 직접 합니다.

순항 중 전후 이동·기체 회전·태그 높이에 따른 상하 보정 명령은 보내지 않습니다.
일반 왕복은 예상 태그가 촬영 허용 영역에 들어온 것으로 각 방문을 확인합니다. 예상하지 않은 번호가
보여도 경로를 건너뛰지 않습니다. 각 방문에는 3초 정지를 둡니다.
벽 태그 1·2·3·6은 번호와 영상 중심·모서리로만 판단하므로 실물 크기를 입력할
필요가 없습니다. 벽까지의 거리나 미확인 3D 자세를 생성하지 않습니다.
태그를 보고 복귀하는 방식이므로 출발 좌표의 센티미터 단위 재현을 보장하지 않습니다.

## 실행

저장소 루트에서 아래 명령을 실행합니다. Windows 실행기는 저장소 안의
`drone-control/.venv/Scripts/python.exe`를 사용합니다. 다른 환경은 `-PythonPath`로
지정합니다. PC 환경 설치는 [새 PC 준비 안내](NEW_PC_SETUP.md)를 참고하세요.
음성 시험과 달리 이 단독 시험에는 Azure 로그인이 필요하지 않습니다.

```powershell
# 계획 확인: 네트워크 연결 없음
./drone-control/trials/START_TAG_SHUTTLE.ps1

# 로컬 준비 점검: 개인 설정과 영상 라이브러리 확인, 네트워크 연결 없음
./drone-control/trials/START_TAG_SHUTTLE.ps1 -Mode Check

# 카메라 인식만: 이동·이륙·짐벌 조작 없음
./drone-control/trials/START_TAG_SHUTTLE.ps1 -Mode Camera -PhoneIp "휴대폰IP"

# 실제 이륙과 좌우 왕복 시험
./drone-control/trials/START_TAG_SHUTTLE.ps1 -Mode Flight -PhoneIp "휴대폰IP"

# ID1 + 왼쪽 TV 모크 촬영만: 6 → 1, ID1에서 호버링하고 RC로 반환
./drone-control/trials/START_TAG_SHUTTLE.ps1 -Mode ID1 -PhoneIp "휴대폰IP"

# 현재 요청: 1.5m, 첫 ID1에서 모크 포함 촬영 후 2→3→2→1→6까지 계속 순찰
./drone-control/trials/START_TAG_SHUTTLE.ps1 -Mode Patrol -PhoneIp "휴대폰IP"
```

실제 IP 주소로 바꿔 실행합니다. 카메라 단독 시험에서는 RC로 카메라 방향을
맞춥니다. 카메라 시험을 종료한 뒤 비행 시험을 실행합니다. 다른 PC 비행 실행기가
같은 앱의 제어·영상 연결을 동시에 사용하지 않도록 합니다.

기본 개인 설정 경로는 `drone-control/pc/config.tag-shuttle.local.json`입니다.
새 PC에서는 기존 개인 설정을 비공개로 옮기거나 `-ConfigPath`로 지정합니다.
키·arm token은 출력하거나 Git에 올리지 않습니다. 실행 때 현재 휴대폰 IP를
명시하므로 과거 PC의 주소를 자동으로 재사용하지 않습니다.

시험 프로필은 `trials/profiles/standalone_tag_6321236.json`의 schema 2입니다.
파일명은 기존 실행기 호환을 위해 유지하며, 실제 내용은 사용자가 수정 확인한
배치 3·2·1·6과 방문 순서 6→1→2→3→2→1→6입니다.
벽 배치·경로는 확인됐으며, `wall_measurement=image_only`로 벽 태그 크기 입력이
필요 없는 경로를 사용합니다. `floor_size_source=private_config`에 따라 바닥 0의
기존 크기·카메라 보정 설정은 유지합니다. 바닥 0은 상승 중 영상 높이 교차 확인에
쓰이고 상승 목표는 하방 센서 표시값입니다. 바닥 태그를 다른 크기로 교체한 경우에는
개인 설정의 0번 크기도 맞춰야 합니다. 다른 태그의 크기를 0번 값으로 덮어쓰지 않습니다.

## 기록과 중단

- 카메라 단독: `pc/logs/tag-camera/<실행ID>/observations.jsonl`, `summary.json`.
  번호, 역할, 영상 중심·모서리, 인식 품질, 프레임 나이와 연결 상태를 기록합니다.
  설정에 크기가 없는 새 태그 6도 번호는 인식하며 미확인 거리값을 만들지 않습니다.
- 비행: 기존 PC JSONL 원시 요청·ACK·센서값과 태그 관측·확인 사진을 기록합니다.
  벽 태그의 미터 단위 거리·자세는 `null`로 기록하고 영상 좌표와 인식 품질을 남깁니다.
- PC 장애물 거리 임계치에 따른 정지는 추가하지 않습니다. 기체 펌웨어의 회피
  설정을 변경하지 않으며 센서의 범위 밖 값·오래된 값도 기록에 보존합니다.
- 실제 `.6` 앱, 최신 지상·모터·RC 상태, 영상과 높이 데이터가 필요합니다.
  배터리 최소 30%, 최대 기울기 1.5도, 구간 45초·전체 240초 범위입니다.
  명령 응답 불명, 연결·제어권 상실, 오래된 영상에서는 자동 재실행하지 않습니다.
- Ctrl+C 또는 오류 시 정지·제어 해제를 시도하고 확인 결과를 출력합니다.
  RC 반환 확인과 실제 착륙 완료는 구분합니다.

## ID1과 TV 모크를 함께 촬영하는 시험

`-Mode ID1`은 바닥 0·하방 1.5m·벽 6을 확인한 뒤 **ID1까지만 이동**합니다.
ID2·ID3 방문이나 벽 6 복귀는 실행하지 않습니다. 촬영 후 정지하고 RC로 제어권을
반환하므로 ID1에서 호버링하며, 착륙은 사용자가 직접 합니다.

최신 사용자 요청은 **`-Mode Patrol`**입니다. 첫 ID1 촬영 후 2→3→2→1→6을
계속 방문하고 마지막 6에서 RC로 반환합니다. 이후 구간도 좌우 최대 0.6도로
이동하며, 첫 ID1 이외에는 태그 촬영을 확인하고 TV 전체 검출을 주장하지 않습니다.

보정 정책 (2026-09-10 저녁 개정): 지나친 경우 0.6초 정지·안정 후 **연속 비례 보정**
(0.25~0.6도)을 태그가 도착 구간에 들어오거나 반대편으로 넘어갈 때까지 유지합니다.
태그가 화면 밖으로 사라지면 정지·안정 후 사라진 방향으로 0.6도 **연속 재탐색**을
마지막 관측 후 6초 안에서 유지하고, 다시 보이면 정지·안정 후 비례 보정으로 넘어갑니다.
근거: 14:51 비행에서 0.25도×0.25초 펄스는 기체를 거의 움직이지 못해(가속 약 0.04 m/s²)
지나친 뒤 33초간 정지만 하다 45초 시간 초과했습니다. 우측 보정 한계도 +0.6도로 맞췄습니다.

사용자가 제공한 사진의 **ID1 왼쪽 모크와 태그 종이 전체**를 합친 영역을
`trials/profiles/id1_tv_pair_reference.json`에 기록했습니다. 보정된 태그 모서리에서
이 영역의 투영 결과는 사진 분석용 진단으로 기록합니다. 현재 도착 기준은 사용자 요청에
따라 **ID1 중심의 가로 위치 90% ±5% (85~95%)**입니다. 태그의 검은 정사각형 전체가
영상 2% 여백 안쪽에 보이면 구간 안의 어느 위치든 인정하며, 정확히 90%를 쫓지 않습니다.
이는 같은 평면·같은 배치를 가정한 예상 영역이며 TV 자체를 검출하거나 거리·크기를
측정한 결과가 아닙니다. 실제 저장 사진에서 모크 전체가 보이는지 확인해야 통과입니다.

좌측 접근은 최대 0.6도이며, 목표 영역이 들어오면 정지합니다. 반대편으로 지나친
경우에는 0.6초 이상 정지하고 수평 속도 0.08m/s 이하를 확인한 후 최대 0.25도의
짧은 우측 보정 후 재확인합니다. 현재 도착 모드에서는 3회만으로 종료하지 않고 기존
구간 45초·전체 240초 안에서 보정을 반복합니다. 각 보정은 PC 기준 0.25초 후 정지를 요청하지만,
네트워크·기체 응답 지연 때문에 물리적 지속 시간이 정확히 0.25초라는 뜻은 아닙니다.
촬영은 1초 이상 정지하고 최신의 서로 다른 프레임에서 태그의 도착 구간·낮은 속도를
확인한 뒤 저장합니다. 추정 모크의 폭이나 세로 여백 미달은 비행 종료 조건이 아닙니다.
태그가 도착 구간 밖이거나 오른쪽으로 잘리면 정지 후 보정하며, 잠깐 사라지면
정지 상태에서 재인식을 기다립니다. 영상·제어 상태가 오래되면 이동을 재개하지 않습니다.
도착과 TV 전체 촬영 성공을 구분해 기록하며, TV 전체 포함 여부는 실제 사진 검토로 확인합니다.
상하·전후·회전 보정을 추가하지 않습니다.

원시 센서·API 요청과 응답·태그 관측에 더해 `id1_pair_framing_sample`,
`id1_pair_capture`에 예상 영역, 보정 방향, 속도, 프레임 번호와 사진 경로를 기록합니다.
`tv_visibility_verified=false`는 실제 사진 검토 전의 상태입니다.
첫 ID1이 실제 검출된 원본 프레임은 `diagnostic_first_ID1.jpg`와 해당 프레임 번호로
별도 저장합니다. 이는 진단 이미지이며 촬영 성공 사진과 구분합니다.
이 완화된 보정 정책의 실제 비행 성능은 아직 검증 전입니다.

14:25 시험에서 하방 1.5m 도달과 자동 제어권 전환을 실제 확인했습니다.
ID6은 22회 정상 인식됐지만 당시 남아 있던 중앙 ±80px 조건으로 출발하지 못했습니다.
현재는 태그 모서리 전체가 영상 3% 여백 안에 보이면 확인하며, 당시 실제 관측 위치를
재생한 회귀 테스트를 통과했습니다. 변경 후 전체 순찰과 ID1 모크 사진은 아직 실기 미검증입니다.
영상 처리 뒤 높이를 다시 조회하며, 무장 ACK 뒤에는 최대 2초 동안 실제 MSDK 제어권
전환을 기다립니다. 이 두 처리에는 자동 재무장이나 비행 재실행이 포함되지 않습니다.

## 검증 상태 (2026-09-10)

- schema 2 포함 PC 단위 테스트 187개 통과. 이 중 단독 왕복 테스트는 31개입니다.
- 실제 설치된 PyAV/OpenCV/pupil로 합성 이미지 1개와 H.264 영상 6프레임에서
  ID 0·1·2·3·6을 모두 인식했습니다. 설정에 6번이 없어도 인식하며 벽의 거리·자세는
  `null`, 바닥 0만 기존 크기를 사용한 실제 검출값으로 기록하는 것을 확인했습니다.
  이는 합성 영상 검증이며 실제 비행 측정 결과가 아닙니다.
- 현재 PC의 개인 설정으로 `-Mode Check` 통과: 카메라 보정값, 바닥 0의 0.15m 설정,
  설치된 영상 라이브러리를 확인했습니다. 기체·네트워크 연결은 열지 않았습니다.
- PowerShell 계획 실행, 문법, 잘못된 IP의 연결 전 거절 확인.
- 오프라인 영상 검증 증거는 Git 제외 경로
  `pc/logs/tag-shuttle-local-check/mixed-detector-result.json`에 보관했습니다.
- `.6` 앱 연결과 이륙·바닥 0·하방 1.4m·벽 6 확인을 실제 수행했습니다.
  13:53 시험에서는 ID1을 55회 검출했지만 이전 중심 정렬 조건이 반복 보정을 일으켜
  45초 안에 방문 확인에 실패했습니다. 사용자가 수동 착륙 완료를 확인했습니다.
  새 ID1 모크 촬영 방식의 실기 성공을 의미하지 않습니다.
- 벽 배치·방문 순서는 사용자 확인 완료. schema 2는 벽 태그의 실물 크기나 크기 확인
  플래그를 사용하지 않습니다. 바닥 0의 기존 보정 설정은 유지합니다.
- 사용자 요청에 따라 schema 2 변경은 로컬에만 보관하며 GitHub에 푸시하지 않습니다.

## 첫 실기 연결 점검에서 확인한 수정 사항

2026-09-10 13:31 점검에서 `.5` 앱의 기체 연결 generation은 1이지만 센서 구독은
generation 0으로 남아 RC 제어권과 장애물 정보가 비어 있었습니다. 이륙 명령은
보내지 않았습니다. 영상은 21개 최신 프레임을 수신했으며 지상 정면 영상에서는
태그가 보이지 않았습니다.

`.6`은 기체 연결이 확인된 후 구독을 설치합니다. 또한 모터 상태 GET을 다른 핵심
